## 1. 한 문장으로

**Tether는 로봇과 자동차가 연습하는 가상 세계(시뮬레이터)를 실제 세계에 맞게 고쳐 주는 도구입니다.**

### 비유: 틀린 지도 고치기

내비게이션 지도에는 도로 전체가 마른 아스팔트로 되어 있습니다. 실제로는 8 m 지점부터 비에 젖어 있습니다. 지도만 믿고 브레이크를 밟으면 차가 매번 정지선을 지나칩니다.

Tether는 실제로 멈춘 기록을 보고 "8.6 m 지점부터 젖어 있고, 그 구간의 마찰은 0.29입니다"처럼 지도를 고칩니다. 고친 지도로 다시 연습하면 실제 도로에서도 정지선에 맞춰 섭니다.

### 어떤 문제를 푸는가

1. 로봇과 자율주행 차량은 실제로 움직이기 전에 시뮬레이터에서 수천 번 연습합니다. 실제로 연습하면 느리고 비싸고 위험하기 때문입니다.
2. 그런데 시뮬레이터는 현실과 조금씩 다릅니다. 탁자가 더 미끄럽거나, 바닥 일부가 젖어 있거나, 모터 힘이 약하거나, 카메라가 기울어 있습니다.
3. 그래서 시뮬레이터에서 98% 성공하던 로봇이 실제로는 빗나갑니다. 이 차이를 **Sim2Real 격차**(시뮬레이션과 현실의 차이)라고 부릅니다.
4. 지금은 엔지니어가 실패를 보고 원인을 짐작해 시뮬레이터를 손으로 고칩니다. 한 번 고치는 데 며칠씩 걸립니다.
5. Tether는 이 과정을 자동으로 합니다. 무엇이 다른지 찾고, 얼마나 확실한지 숫자로 말하고, 고친 시뮬레이터로 다시 학습까지 시킵니다.

## 2. Tether가 하는 일

```
 입력                 측정               진단 (AI)              보정
 ─────────────       ─────────────      ─────────────────      ─────────────────
 스마트폰 영상   ──▶  출발 속도,     ──▶  Nemotron이 원인의  ──▶  마찰, 다른 구간,
 로봇·차량 로그       멈춘 위치,          종류를 고르고,         모터 힘, 카메라
 가상 데이터          감속을 잰다         수학이 값을 계산         값 + 오차 범위
                                                                     │
                                                                     ▼
 내보내기             검증                재학습                 
 ─────────────       ─────────────      ─────────────────      
 Newton, Isaac Lab, ◀── Newton에서    ◀── 고친 시뮬레이터로 ◀────┘
 CARLA 설정, 보고서     모든 시행 재현      정책을 다시 학습
```

| 단계 | 하는 일 | 누가 하나 |
|---|---|---|
| 입력 | 영상(A4 용지를 옆에 두고 촬영), 로봇·차량이 이미 남기는 로그, 또는 가상 데이터 | 사용자 |
| 측정 | 물체를 추적해 시행마다 출발 속도와 멈춘 위치를 잽니다 | Tether (영상 처리) |
| 진단 | "탁자 전체가 미끄러운가, 중간부터 미끄러운가" 같은 가설을 세우고 하나씩 검증합니다 | NVIDIA Nemotron (AI) |
| 보정 | 각 값과 90% 오차 범위를 계산합니다 | 수학 계산 (최소제곱 피팅, 부트스트랩) |
| 재학습 | 고친 시뮬레이터로 정책을 다시 학습하고, 숨겨진 실제 환경에서 채점합니다 | NVIDIA Newton (병렬 세계 16개) |
| 검증·내보내기 | 모든 시행을 Newton에서 다시 실행해 확인하고, 설정 파일로 내보냅니다 | NVIDIA Newton |

**핵심 원칙:** AI는 숫자를 짐작하지 않습니다. AI는 "어떤 종류의 차이가 있는가"를 고르고 추가 실험을 요청합니다. 실제 값과 오차 범위는 항상 수학 계산으로 구합니다. AI가 고른 모델이 증거를 설명하지 못하면 교차 검증이 AI의 판단을 뒤집습니다.

### 세 분야, 같은 물리

세 분야 모두 "출발한 물체가 마찰로 미끄러지다 멈추는" 같은 물리입니다. 그래서 같은 엔진과 같은 AI로 처리합니다.

| 분야 | 장면 | 찾는 것 | 내보내기 |
|---|---|---|---|
| 로봇 조작 | 로봇 팔이 상자를 밀어 목표선에 세움 | 탁자 마찰, 젖은 부분, 팔 힘, 카메라 기울기 | Newton, Isaac Lab |
| 자율주행 차량 | 차량이 제동해 정지선에 섬 | 노면 마찰, 젖거나 언 구간, 속도 제어, 전방 카메라 | Newton, CARLA, Isaac Lab |
| 제조 검사 | 푸셔가 부품을 검사 위치로 밂 | 레일 마찰, 기름 묻은 구간, 푸셔 힘, 카메라 기울기 | Newton, Isaac Lab |

### 소개 (`/`)

- 맨 위 그림에서 **보정 전 / 보정 후** 버튼을 눌러 봅니다. 보정 전에는 시뮬레이터의 예측과 실제 정지 위치가 어긋나고, 보정 후에는 겹칩니다.
- **분야를 고르세요**: 세 분야 카드의 **예시 열기**로 Studio 예시를 바로 엽니다.
- **결과**: 핵심 숫자 세 개(96–100%, 89%, 5개 중 4개)가 있습니다. 6절에서 설명합니다.

### Studio (`/studio`)

왼쪽에 세 단계가 있습니다.

1. **데이터**: 분야(로봇 조작, 자율주행 차량, 제조 검사)를 고르고 시작 방법을 고릅니다.
   - **예시로 보기**: 정답을 아는 준비된 데이터
   - **가상 데이터 만들기**: 숨길 물리값을 직접 정하면 NVIDIA Newton이 영상이나 로그를 만듭니다
   - **내 데이터 올리기**: 직접 찍은 영상이나 로그 파일
2. **분석**: 영상이면 먼저 물체를 추적하고, 이어서 AI가 원인을 찾습니다. 로그는 바로 분석합니다.
3. **결과**: 탭 세 개입니다.
   - **보정된 시뮬레이터**: 무엇이 다른지, 오차 범위, 마찰 지도, 다음 실험 추천
   - **재학습**: 세 가지 조건으로 다시 학습한 정책의 성공률
   - **내보내기**: Newton 재현 검증, 설정 파일, 보고서

오른쪽 아래 **질문** 버튼을 누르면 **Tether에게 물어보기** 창이 열립니다.

### 검증 (`/benchmark`)

- 맨 위 제목과 설명이 이 화면의 목적입니다: 정답을 아는 세계에서 AI를 시험합니다.
- 모든 예시는 같은 과제입니다(로봇 팔로 상자를 목표선에 세우기). 탭마다 실제 환경에 숨긴 원인이 다릅니다.
- 탭: 젖은 구간, 거친 구간, 렌즈 왜곡, 원인 3개 동시 발생, 미끄러운 상자, 틀어진 카메라 등.
- **AI 실험 노트**에 Nemotron이 가설을 세우고(H1, H2, H3) 맞았는지 틀렸는지 확인하는 과정이 그대로 나옵니다.
- **+ AI에게 문제 내기**: 직접 원인을 숨기고 AI가 찾는지 시험합니다.
- **벤치마크**: 규칙 기반, 자동 탐색, 도메인 랜덤화, Nemotron AI의 성공률 비교입니다.

## 4. 할 수 있는 것과 할 수 없는 것

### 할 수 있는 것

- 영상 하나로 거리와 카메라 위치를 계산합니다. 필요한 것은 A4 용지 한 장(자율주행은 도로 위 크기를 아는 사각형)입니다.
- 마찰, 마찰이 다른 구간(시작 위치와 마찰), 모터·푸셔 힘, 카메라 기울기를 찾습니다.
- 각 값이 얼마나 확실한지 90% 오차 범위로 보여 줍니다. 측정하지 않은 구간은 "미측정"이라고 표시하고 단정하지 않습니다.
- 어디를 더 측정하면 가장 확실해지는지 **다음 실험**으로 알려 줍니다.
- 고친 시뮬레이터로 정책을 다시 학습하고, 정답을 아는 경우 숨겨진 환경에서 채점합니다.
- NVIDIA Newton, Isaac Lab, CARLA(자율주행)용 설정 파일과 보고서를 내보냅니다.
- 결과에 대한 질문에 한국어와 영어로 답합니다.

### 할 수 없는 것 (솔직한 한계)

- 물리는 "밀거나 제동해서 미끄러져 멈추는 동작" 하나입니다. 집기, 쌓기, 조향, 차선 변경은 다루지 않습니다.
- 물체가 넘어지는 경우는 계산에서 제외합니다.
- 결과 대부분은 정답을 알 수 있는 가상 데이터(NVIDIA Newton, MuJoCo)로 검증했습니다. 실제 물체 검증은 공개 벤치마크(EV-RealPhys)로 했고, A4 용지로 직접 찍은 휴대폰 영상의 결과는 아직 없습니다.
- 실제 데이터에서는 오차 범위가 너무 좁게 나옵니다(정답 포함 5개 중 3개, 2개).
- CARLA 설정 파일은 CARLA 공식 API와 맞춰 확인했지만, CARLA 자체에서 실행해 보지는 않았습니다(GPU 서버가 필요합니다).
- 실제 로봇 하드웨어는 없습니다.

## 5. 직접 테스트하기

### 시작 전에

- 주소: https://tether-454741001655.us-central1.run.app (오른쪽 위 **KO**로 한국어 전환)
- 한동안 아무도 접속하지 않으면 서버가 꺼집니다. 첫 접속은 서버가 켜지는 데 **10~20초** 걸립니다. 시연 전에 미리 한 번 열어 두십시오.

| 작업 | 공개 데모에서 걸리는 시간 |
|---|---|
| 페이지 열기 (서버가 켜진 상태) | 1초 안팎 |
| 영상 추적 | 약 30초 |
| AI 분석 (Nemotron) | 약 40초 |
| 질문 답변 | 약 2초 |
| 재학습 | 약 3분 (화면에는 "약 1분"이라고 나오지만, 공개 서버는 CPU 하나로 계산해 더 걸립니다. 정상입니다) |

### 5-1. 5분 둘러보기

1. 소개 화면에서 **보정 전 / 보정 후**를 번갈아 눌러 봅니다. 시뮬레이터 예측(위)과 실제(아래)가 어긋났다가 맞춰지는 것을 확인합니다.
2. **AI 검증 보기**를 눌러 검증 화면으로 갑니다. 맨 위 설명과 **예시 하나가 진행되는 순서 (30초)**를 읽고 **닫기**를 누릅니다.
3. **원인 3개 동시 발생** 탭을 누르고 **결과 바로 보기**를 누릅니다. 보정 전 0% → 보정 후 100%를 확인합니다.
4. 아래 **AI의 실험 노트**를 읽습니다. 가설 H1이 맞는 것 같았지만, 추가로 멀리 밀어 보니(probe) H2가 틀렸고, 0.40 m부터 미끄러운 구간을 넣은 H3가 맞았습니다.
5. **정답 보기**를 눌러 AI가 맞혔는지 확인합니다.
6. 위 메뉴의 **Studio**로 가서 다음 시나리오를 진행합니다.

### 5-2. Studio 예시로 끝까지 (약 6분)

자율주행 예시가 가장 직관적입니다.

1. Studio에서 분야 **자율주행 차량**을 고릅니다.
2. 시작 방법 **예시로 보기**에서 **도로변 카메라: 정지선 제동** 카드를 누릅니다. 도로 일부가 젖어 있는 영상입니다(NVIDIA Newton으로 만든 가상 영상).
3. **이동 거리 측정** 화면이 나옵니다. 초록 점 4개가 도로 위 기준 사각형(5.25 × 7.43 m) 모서리에 미리 맞춰져 있습니다. **움직임 추적하기**를 누릅니다(약 30초).
4. 추적이 끝나면 **원인 분석**이 이어집니다. **AI 분석 기록**에 Nemotron이 한 일이 한 줄씩 나타납니다(약 40초). 끝나면 **보정된 시뮬레이터 보기**를 누릅니다.
5. **보정된 시뮬레이터** 탭에서 확인할 것:
   - 도로 위에 마찰이 색으로 칠해져 있습니다(파란색일수록 미끄러움). 젖은 구간이 따로 표시됩니다.
   - **시뮬레이터와 다른 값** 표: 노면 마찰, 젖은 구간 시작 위치, 그 구간의 마찰과 각각의 오차 범위.
   - **다음 실험**: 어디까지 더 제동해 보면 가장 확실해지는지.
6. **2번째 영상 불러오기: 추천 실험**을 누릅니다. 추천대로 더 찍은 영상이 추가되고 다시 추적·분석합니다. 오차 범위가 좁아집니다.
7. **정답 확인하기**를 누릅니다. 표에 정답이 나타납니다. 기록된 실행 기준으로 Tether는 노면 마찰 0.740(정답 0.75), 젖은 구간 8.60 m부터(정답 8.82 m), 구간 마찰 0.294(정답 0.30)를 찾았습니다. 실행마다 소수점 아래는 조금 다를 수 있습니다.
8. **재학습** 탭에서 **NVIDIA Newton에서 재학습**을 누릅니다(약 3분). 세 조건의 숨겨진 환경 성공률이 나옵니다. 기록된 실행 기준으로 보정 전 시뮬레이터 29%, 넓은 도메인 랜덤화 8%, Tether 측정 범위 96%입니다.
9. **내보내기** 탭에서 **NVIDIA Newton으로 재현하기**를 누릅니다(몇 초). 모든 시행을 Newton에서 다시 실행해 보정값과 보정 전 값의 오차를 비교합니다.
10. 아래 파일 탭 **NVIDIA Newton / CARLA / Isaac Lab / 보고서 / JSON**을 눌러 봅니다. **복사**, **다운로드**로 가져갑니다.

빨리 보려면 2번에서 **차량 로그: 정지선 제동**을 고릅니다. 로그라서 추적 없이 바로 AI 분석으로 넘어갑니다.

### 5-3. 가상 데이터 만들기: 내가 숨긴 값을 맞히는가 (약 3분)

"정답을 미리 정해 두고 Tether가 찾는지 보는" 시험입니다. 시연에서 가장 설득력이 있습니다.

1. Studio에서 분야 **로봇 조작**, 시작 방법 **가상 데이터 만들기**를 고릅니다.
2. **스마트폰 영상** 또는 **로봇 로그**를 고릅니다. 로그가 더 빠릅니다.
3. 숨길 값을 정합니다. 기본값은 다음과 같습니다.
   - **탁자 마찰계수** 0.45
   - **마찰이 다른 구간 추가**: **구간 시작 거리** 0.32 m, **구간 마찰계수** 0.25
   - **밀기 횟수** 7, **최대 이동 거리** 0.42 m
   - 로그를 고르면 **로봇 모터 출력**과 **로봇 카메라 기울기**도 정할 수 있습니다.
4. **NVIDIA Newton으로 만들기**를 누릅니다. Newton이 정한 물리대로 데이터를 만듭니다. Tether는 이 설정을 볼 수 없습니다.
5. 영상이면 **움직임 추적하기**, 로그면 바로 분석이 진행됩니다.
6. 결과에서 **정답 확인하기**를 눌러 비교합니다. 예전에 같은 설정으로 실행했을 때 마찰 0.451(정답 0.45), 구간 시작 0.322 m(정답 0.32), 구간 마찰 0.254(정답 0.25)였습니다.
7. 처음에는 구간까지 간 시행이 적어 오차 범위가 넓습니다. **추천 실험을 NVIDIA Newton에서 실행**을 누르면 추천대로 더 밀어 보고 범위가 좁아집니다.

값을 바꿔 가며 시험해 보십시오. 예를 들어 구간을 아주 멀리(최대 이동 거리보다 뒤) 두면, Tether는 그 구간을 단정하지 않고 "미측정"이라고 표시해야 정상입니다.

### 5-4. Tether에게 물어보기 (1분)

1. Studio 아무 단계에서나 오른쪽 아래 **질문**을 누릅니다.
2. 추천 질문(예: "이 도구는 무엇을 합니까?", "영상은 어떻게 촬영합니까?")을 누르거나 직접 입력하고 **보내기**를 누릅니다.
3. 결과가 나온 뒤에 물어보면 현재 결과의 숫자로 답합니다. 시험해 볼 질문:
   - "마찰이 얼마로 나왔고 얼마나 확실합니까?"
   - "다음에 무엇을 더 측정하면 됩니까?"
   - "보정 전 시뮬레이터와 무엇이 다릅니까?"
4. 정답은 **정답 확인하기**를 누른 뒤에만 답변에 반영됩니다(그 전에는 AI도 정답을 모릅니다).
5. 질문은 한 세션에 30번까지입니다.

### 5-5. 내 영상 올리기 (촬영 15분 + 분석 2분)

자세한 촬영법은 [06_실제_영상_촬영법.md](06_실제_영상_촬영법.md)에 있습니다. 요약:

### 5-6. 검증 화면에서 문제 내기 (약 5분)

1. 검증 화면에서 **+ AI에게 문제 내기**를 누릅니다.
2. 예시 버튼(**젖은 구간**, **거친 구간**, **렌즈 왜곡**, **원인 3개 동시 발생**, **무작위**) 중 하나를 누르거나, 슬라이더로 직접 숨길 값을 정합니다. 오른쪽 **내가 숨긴 것**에 정한 값이 보입니다(최대 3개).
3. **AI 실행**을 누릅니다. AI가 시뮬레이터에서 학습하고, 숨겨진 환경에서 시행하고, 원인을 찾아 고친 뒤 다시 학습합니다. 몇 분 걸립니다.
4. 실험 노트가 한 단계씩 나타납니다. 끝나면 숨긴 값과 AI가 찾은 값을 비교합니다.
5. 한 사람당 한 시간에 6번까지 실행할 수 있습니다.

## 6. 결과 숫자 읽는 법

| 숫자 | 뜻 | 왜 중요한가 |
|---|---|---|
| **마찰 μ** (예: 0.74) | 미끄러지는 정도입니다. 0.2는 얼음처럼 미끄럽고, 1.0은 고무처럼 잘 잡힙니다. 마른 아스팔트는 약 0.8, 젖은 노면은 약 0.4입니다 | 마찰이 틀리면 멈추는 위치가 틀립니다. 멈추는 거리 = 속도² ÷ (2 × 마찰 × 9.81) |
| **90% 오차 범위** (예: 0.720–0.750) | 실제 값이 이 안에 있을 가능성이 90%라는 뜻입니다. 좁을수록 확실합니다 | 무작위 가상 세계 24개(값 118개)에서 실제로 97%가 범위 안에 들어갔습니다. 범위를 믿을 수 있다는 근거입니다 |
| **보정 전 → Tether 보정** (예: 30% → 52%) | 결과 첫 화면의 성공률은 모델로 **예측**한 값입니다 | 실제로 측정한 값은 재학습 탭에서 나옵니다 |
| **재학습 성공률 42% / 0% / 100%** | 차량 로그 예시에서 세 가지 시뮬레이터로 학습한 정책을 숨겨진 실제 환경에서 시험한 결과입니다(목표 24개). 보정 전 시뮬레이터 42%, 넓은 도메인 랜덤화 0%, Tether 100% | 보정 전 시뮬레이터는 "확신에 찬 틀린 답", 넓은 랜덤화는 "어디서나 어중간한 답"입니다. Tether는 측정한 범위만 써서 맞춥니다 |
| **96–100%** (소개 화면) | 예시 6개 중 5개에서 Tether 범위로 재학습한 정책의 성공률입니다(보정 전 0~63%) | 나머지 1개(짧은 거리만 시행)는 46%입니다. 먼 구간을 측정하지 않았기 때문이며, Studio가 미리 그렇게 경고합니다 |
| **실제 물체 5개 중 4개** | 공개 연구 데이터(EV-RealPhys, 막스플랑크 연구소)에서 실제 물체 5개의 마찰을 쟀습니다. 정답은 탁자를 기울여 따로 잰 값이고 Tether는 보지 않았습니다. 4개가 정답과 ±0.05 이내입니다 | 가상 데이터가 아니라 **실제 물체와 실제 영상**에서도 맞는다는 근거입니다. 평균 오차는 영상 0.029로, 같은 데이터에서 논문 저자들의 방법(0.082)보다 정확합니다. 크래커 상자는 틀렸습니다 |
| **다른 엔진 89% vs 12%** | "실제" 데이터를 Tether가 쓰는 Newton이 아닌 다른 물리 엔진(MuJoCo)으로 만들었습니다. Tether 보정 89%, 가장 좋은 도메인 랜덤화 12%입니다(세계 24개) | 같은 엔진으로 만들고 같은 엔진으로 맞추면 "자기 확인"에 불과하다는 반론에 대한 답입니다. 모델에 없는 효과(속도에 따른 마찰, 두 번째 구간, 기울어진 탁자)를 넣어도 83~90%였습니다 |
| **남은 오차 9.3 cm rms** | 보정된 시뮬레이터가 실제 정지 위치와 평균 얼마나 다른지입니다 | 작을수록 시뮬레이터가 현실을 잘 따라갑니다 |

## 7. 어떻게 설명할까

### 10초

> Tether는 시뮬레이터가 현실과 다른 부분을 영상이나 로그로 찾아 고쳐 주는 도구입니다. 고친 시뮬레이터로 다시 학습한 로봇은 실제에서도 성공합니다.

### 30초

> 로봇과 자율주행 차량은 시뮬레이터에서 먼저 연습합니다. 그런데 실제 바닥은 더 미끄럽거나 일부가 젖어 있어서, 시뮬레이터에서 잘 되던 동작이 실제로는 빗나갑니다.
> Tether는 휴대폰 영상이나 로봇이 이미 남기는 로그를 보고, NVIDIA Nemotron AI가 무엇이 다른지 가설을 세워 검증합니다. 숫자는 수학으로 계산하고, 얼마나 확실한지 오차 범위로 보여 줍니다.
> 고친 시뮬레이터로 NVIDIA Newton에서 다시 학습하면, 예시 차량의 성공률이 42%에서 100%로 오릅니다.

### 2분

> 로봇을 실제로 연습시키면 느리고 비싸고 위험합니다. 그래서 시뮬레이터에서 수천 번 연습시킵니다. 문제는 시뮬레이터가 현실과 조금씩 다르다는 점입니다. 탁자가 더 미끄럽거나, 바닥 일부가 젖어 있거나, 모터가 약합니다. 그래서 시뮬레이터에서 거의 매번 성공하던 로봇이 실제로는 빗나갑니다. 지금은 엔지니어가 원인을 짐작해 손으로 고치고, 한 번에 며칠씩 걸립니다.
>
> Tether는 이 일을 자동으로 합니다. 입력은 A4 용지를 옆에 두고 찍은 휴대폰 영상이나, 로봇·차량이 이미 남기는 로그입니다. 용지 크기로 거리와 카메라 위치를 계산하고, 시행마다 출발 속도와 멈춘 위치를 잽니다.
>
> 그다음 NVIDIA Nemotron이 과학자처럼 일합니다. "탁자 전체가 미끄러운가, 중간부터인가"를 가설로 세우고, 계산으로 검증하고, 판단이 어려우면 어디를 더 측정할지 요청합니다. 숫자는 AI가 짐작하지 않고 수학으로 구하며, 모든 값에 90% 오차 범위를 붙입니다.
>
> 고친 시뮬레이터로 NVIDIA Newton의 병렬 세계 16개에서 다시 학습합니다. 차량 예시에서 보정 전 시뮬레이터는 42%, 넓게 무작위화한 방법은 0%, Tether는 100%였습니다. 결과는 NVIDIA Newton, Isaac Lab, CARLA 설정 파일로 내보냅니다.
>
> 검증도 했습니다. 다른 물리 엔진으로 만든 세계에서 89%(가장 좋은 무작위화 12%), 실제 물체 5개 중 4개에서 따로 잰 마찰과 ±0.05 이내였습니다. 한계도 분명히 말합니다. 미끄러져 멈추는 동작 하나만 다루고, 실제 데이터에서는 오차 범위가 아직 좁게 나옵니다.

### English, 30 seconds

> Robots and self-driving cars learn in simulators, but the real world is a little different: a slicker table, a wet patch of road, a weaker motor. So a policy that works in simulation misses in reality.
> Tether reads how things really slide and stop, from a phone video or the log a robot already writes. NVIDIA Nemotron on Nebius Token Factory proposes what differs and asks for the experiments that settle it; the math computes every value with an honest interval.
> Retrained on the corrected physics in NVIDIA Newton, the example car goes from 42% to 100% at the stop line, and Tether exports configs for Newton, Isaac Lab and CARLA.

## 8. 예상 질문과 답

**Q1. 왜 AI가 필요합니까? 계산만으로 안 됩니까?**
계산만 쓰는 방식(정해진 후보 모델을 순서대로 맞춰 보는 시스템 식별)도 성능은 비슷합니다(아주 어려운 문제에서 97% 대 96%). AI가 더하는 것은 세 가지입니다. 정해진 순서 없이 어떤 효과를 의심할지 스스로 고르고, 어디를 더 측정할지 실험을 요청하고, 왜 그렇게 고쳤는지 설명합니다. 계산 방식보다 낫다고 주장하지 않습니다.

**Q2. AI가 틀리면 어떻게 됩니까?**
AI는 모델의 종류만 고르고, 숫자는 계산이 구합니다. AI가 고른 모델이 증거를 설명하지 못하면 교차 검증이 뒤집습니다. 예: 짧은 거리만 시행한 로그에서 Nemotron이 0.25 m에 구간이 있다고 제안했지만, 개선이 0.8 mm로 잡음 수준이라 교차 검증이 뺐습니다.

**Q3. 실제 데이터로도 됩니까?**
공개 연구 데이터(EV-RealPhys)의 실제 물체 5개 중 4개에서 따로 잰 마찰과 ±0.05 이내였습니다. 공개 실제 슬로모션 영상 52개 중 45개를 추적했고, Tether의 물리 모델(일정한 감속)이 실제 움직임을 잘 설명했습니다(R² 중앙값 0.9985). A4 용지로 직접 찍은 휴대폰 영상의 결과는 아직 없습니다.

**Q4. 정답은 어떻게 압니까?**
가상 데이터는 숨길 물리값을 먼저 정하고 NVIDIA Newton으로 데이터를 만듭니다. Tether는 그 값을 모른 채 데이터만 받고, 분석이 끝난 뒤에 정답을 공개해 채점합니다.

**Q5. 같은 엔진으로 만들고 같은 엔진으로 맞추면 당연히 맞는 것 아닙니까?**
맞는 지적이라 두 가지를 더 했습니다. 다른 물리 엔진(MuJoCo)으로 만든 세계에서 89%(가장 좋은 도메인 랜덤화 12%), 그리고 실제 물체 벤치마크입니다.

**Q6. 도메인 랜덤화와 무엇이 다릅니까?**
도메인 랜덤화는 모르는 값을 넓게 흔들어 학습합니다. 그러면 어디서나 어중간한 정책이 나옵니다(예시에서 0~38%). Tether는 실제로 잰 범위 안에서만 흔들어 학습합니다(96~100%).

**Q7. NVIDIA와 Nebius는 어디에 썼습니까?**
NVIDIA Newton으로 물리 계산, 영상 렌더링, 재학습, 재현 검증을 합니다. NVIDIA Nemotron 3 Super를 Nebius Token Factory에서 호출해 원인 진단과 질문 답변을 합니다. 같은 AI를 NVIDIA NeMo Agent Toolkit 워크플로로도 실행할 수 있습니다. 선택 기능으로 NVIDIA Cosmos Reason 2가 영상에서 물체가 넘어졌는지 판단합니다.

**Q8. 비용은 얼마입니까?**
AI 질문 1회 약 $0.002, AI 진단 1회 약 $0.01입니다. 검증 화면의 벤치마크는 세계 하나에 약 $0.007입니다. 물리 계산은 CPU로 해서 GPU가 필요 없습니다. 공개 서버는 접속이 없으면 꺼져서 거의 비용이 들지 않습니다.

**Q9. 실제 로봇이 있습니까?**
없습니다. 하드웨어 없이 영상과 로그만으로 동작하는 도구입니다. 해커톤 Physical AI 트랙은 하드웨어가 없으면 애플리케이션이 동작하는 모습을 보여 주도록 되어 있습니다.

**Q10. 영상 하나로 어떻게 실제 거리를 압니까?**
A4 용지는 크기가 정해져 있습니다. 화면에서 용지가 찌그러져 보이는 모양으로 카메라 높이와 각도를 계산합니다. 물체 높이를 입력받는 이유는 카메라가 물체 바닥이 아니라 중심을 보기 때문입니다. 가상 영상 기준으로 이동 거리 오차 1 mm 이내, 출발 속도 오차 0.6%였습니다.

**Q11. 자동차와 상자가 어떻게 같은 물리입니까?**
바퀴가 잠기거나 ABS로 제동할 때 차는 마찰로 미끄러지다 멈춥니다. 상자와 같은 식입니다. 크기는 1:25로 줄여 계산하고(길이 25배면 속도 5배, 마찰은 그대로) 화면과 파일에는 실제 크기로 표시합니다.

**Q12. 오차 범위는 믿을 수 있습니까?**
가상 세계에서는 90% 범위가 실제로 97% 맞았습니다. 실제 데이터에서는 범위가 너무 좁아 5개 중 2~3개만 정답을 포함했습니다. 이 점은 한계로 밝힙니다.

## 10. 저장소 구조 (폴더 지도)

맨 위 폴더는 역할별로 나뉩니다. 앱 코드는 모두 `tether/` 안에 있고, 나머지는 데이터, 테스트, 영상, 배포, 문서입니다.

```
tether/                    앱 코드 (파이썬 패키지 하나)
├── web/                   화면 세 개와 빌더
│   ├── overview.html      /            소개
│   ├── studio.html        /studio      Studio (내 데이터로 보정)
│   ├── benchmark.html     /benchmark   검증 (정답을 아는 세계에서 AI 시험)
│   ├── shared/base.css    세 화면이 같이 쓰는 디자인
│   └── build.py           web/dist/ 에 서버용·단독 실행용 페이지를 만듭니다
├── server/                웹 서버(FastAPI): 화면과 API를 내보냅니다
├── studio/                Studio의 계산 엔진: 영상 추적, 피팅과 오차 범위, 재학습, Newton 검증, 내보내기, 질문 답변
├── agent/                 AI: Nemotron 도구 에이전트, Token Factory 연결, 보정 반복 과정, Cosmos(선택)
├── sim/                   물리: 과제와 계산 모델, NVIDIA Newton 세계, MuJoCo(두 번째 엔진)
├── eval/                  검증 실험과 make prove (모든 핵심 숫자를 다시 계산)
└── paths.py               폴더 위치를 한곳에 모아 둔 파일
runs/                      화면과 테스트가 읽는 기록 데이터 (demo: 검증 화면, studio-demo: Studio 예시, proof: 핵심 숫자)
tests/                     오프라인 테스트 (make check, 네트워크·크레딧 없이 실행)
integrations/nat_tether/   NVIDIA NeMo Agent Toolkit 워크플로
film/                      데모 영상 만들기와 제출 폴더 만들기 (결과물은 film/out/, submission/)
deploy/                    Google Cloud Run 배포 (make deploy)
docs/                      guide/(이 안내서들), submission/(제출 문구), article/(기술 글), project/(작업 기록)
```

| 화면 | 화면 파일 | 서버 | 계산 |
|---|---|---|---|
| 소개 `/` | `tether/web/overview.html` | `tether/server/app.py` | 없음 (Studio 예시와 검증 화면으로 연결) |
| Studio `/studio` | `tether/web/studio.html` | `tether/server/studio_api.py` | `tether/studio`, `tether/agent`, `tether/sim` |
| 검증 `/benchmark` | `tether/web/benchmark.html` | `tether/server/app.py` | `tether/agent`, `tether/sim`, 기록 `runs/demo` |

명령은 모두 `make` 하나로 실행합니다(`Makefile`에 용도별로 묶여 있습니다): `make serve`(서버), `make check`(테스트), `make deploy`(배포), `make film`(영상), `make submission`(제출 폴더).

## 12. 용어 사전

| 용어 | 뜻 |
|---|---|
| 시뮬레이터 | 컴퓨터 안의 가상 세계. 물체가 어떻게 움직일지 물리 법칙으로 계산합니다 |
| Sim2Real 격차 | 시뮬레이터와 현실의 차이 때문에, 시뮬레이터에서 된 것이 실제로는 안 되는 문제 |
| 정책 (policy) | 로봇이 상황마다 어떻게 움직일지 정한 규칙. 여기서는 "목표 거리마다 얼마나 세게 밀지" 표 |
| 재학습 | 고친 시뮬레이터에서 정책을 다시 연습시키는 일 |
| 마찰계수 μ | 미끄러지는 정도. 작을수록 미끄럽습니다 (0.2 얼음 같음, 1.0 고무 같음) |
| 다른 구간 | 바닥 일부의 마찰이 다른 곳 (젖은 곳, 매트, 기름 묻은 곳) |
| 모터 출력 / 액추에이터 게인 | 명령한 힘 대비 실제로 나오는 힘의 비율. 0.88이면 명령보다 12% 약합니다 |
| 90% 오차 범위 (신뢰 범위) | 실제 값이 들어 있을 가능성이 90%인 범위 |
| 최소제곱 피팅 | 측정값과 모델 예측의 차이가 가장 작아지도록 값을 찾는 계산 |
| 부트스트랩 | 측정 기록을 여러 번 다시 뽑아 반복 계산해 오차 범위를 구하는 방법 |
| 도메인 랜덤화 (DR) | 모르는 물리값을 넓게 무작위로 바꿔 가며 학습시키는 기존 방법 |
| 시스템 식별 | 정해진 후보 모델을 순서대로 맞춰 보는 계산 방식. AI와 비교하는 기준입니다 |
| 교차 검증 | AI가 고른 모델을 계산 방식의 결과와 비교해, 증거를 설명하지 못하면 뒤집는 장치 |
| 다음 실험 | 모델들의 예측이 가장 크게 갈리는 지점. 여기를 측정하면 불확실성이 가장 많이 줄어듭니다 |
| 미측정 구간 | 어떤 시행도 닿지 않은 곳. Tether는 여기를 단정하지 않습니다 |
